# 교통약자를 위한 스마트 버스 정류소 프로젝트 설계서

## 1. 프로젝트 개요
* **목적:** 시각 장애인, 노약자 등 교통약자가 버스 도착 정보를 쉽고 정확하게 인지하고 이용할 수 있도록 돕는 스마트 정류소 시스템 구축
* **주요 타겟:** 대중교통을 이용하는 교통약자 (저상버스 필요 승객, 시각장애인 등)
* **핵심 기술:** Arduino UNO R4 WiFi, Python (Streamlit, OpenAPI, TTS), PC 모니터 및 스피커

## 2. 시스템 아키텍처 (System Architecture)
본 시스템은 정보 수집 및 UI를 담당하는 **PC(Python/Streamlit)**와 물리적 입출력을 담당하는 **아두이노(Arduino)**로 구성됩니다.

1. **Backend & Frontend (Python / PC)**
   * **데이터 수집:** 공공데이터포털(OpenAPI) 실시간 버스 도착 정보 및 저상버스 정보 조회
   * **웹 UI 구현:** Streamlit을 활용한 키오스크 형태의 화면 제공 (모바일 연동 포함)
   * **음성 출력:** Python TTS (Text-to-Speech) 라이브러리를 활용하여 PC 스피커로 음성 안내
   * **아두이노 통신:** 시리얼(Serial) 또는 WiFi(HTTP/MQTT) 통신을 통해 아두이노와 데이터 송수신
2. **Hardware (Arduino UNO R4 WiFi)**
   * **입력:** 물리 버튼 2개(노선 선택용), 큰 푸시버튼 또는 터치 센서 1개(음성 안내 요청용)
   * **출력:** 네오픽셀(또는 RGB LED) (도착 임박 알림), 부저(도착 알림음)

## 3. 세부 요구사항 및 구현 설계

### 3.1. 실시간 버스 정보 표시
* **구현 방식:** Python에서 OpenAPI를 호출하여 특정 정류소의 데이터를 파싱한 후, Streamlit 화면에 렌더링.
* **표시 항목:** 노선 번호, 도착 예정 시간(분), 남은 정류장 수, 마지막 갱신 시간.
* **갱신 주기:** API 호출 제한을 고려하여 일정 주기(예: 30초~1분)로 자동 갱신.

### 3.2. 저상버스 여부 표시
* **구현 방식:** OpenAPI의 '차량 유형' 데이터를 확인하여 Streamlit 화면에 반영.
* **UI 요소:** 도착 예정 차량 옆에 휠체어 모양 등의 '저상버스 아이콘' 표시. 정보가 없을 경우 '정보 없음' 텍스트 노출.

### 3.3. 관심 버스 선택
* **구현 방식:**
  * 화면 상에 노선 리스트를 띄우고, 아두이노에 연결된 물리 버튼 2개를 사용해 제어.
  * **버튼 1 (다음 노선):** 리스트에서 포커스(선택 박스)를 아래로 이동.
  * **버튼 2 (선택/해제):** 현재 포커스된 노선을 관심 노선으로 등록 또는 해제.
* **피드백:** 선택된 노선은 화면에서 크고 눈에 띄게(색상 반전 등) 강조 표시.

### 3.4. 도착 임박 표시
* **조건:** 선택한 버스가 설정한 시간(예: 3분 또는 2정거장 이내) 내로 접근 시 발동.
* **하드웨어 제어:** Python이 아두이노로 '도착 임박' 신호를 전송하면, 아두이노가 네오픽셀(RGB LED)을 붉은색 점멸 등으로 제어.
* **소프트웨어 제어:** Streamlit 화면 전체에 테두리 애니메이션 효과를 주거나 '도착 임박' 텍스트를 크게 점멸.

### 3.5. 도착 알림 (청각적 피드백)
* **구현 방식:** 도착 임박 상태로 전환되는 순간, 아두이노의 부저를 제어하여 짧은 알림음(비프음) 발생.
* **예외 처리:** 같은 차량에 대해 알림이 중복해서 울리지 않도록 Python 로직에서 차량 ID(또는 도착 정보 상태값)를 기록하여 1회만 발생하도록 제어.
* **설정:** Streamlit 화면 내에 '알림 켜기/끄기' 토글 메뉴 구성.

### 3.6. 큰 글씨 안내
* **구현 방식:** 교통약자(저시력자 등)를 위한 고대비, 큰 폰트 UI 모드.
* **기능:** Streamlit 내 '큰 글씨 모드' 버튼 클릭 시, 관심 노선의 번호와 도착 시간만 화면 전체에 꽉 차게 렌더링. 직관적인 색상과 아이콘을 적극 활용.

### 3.7. 간편 안내 요청 및 음성 안내
* **구현 방식:** 아두이노에 연결된 큰 푸시버튼(혹은 정전식 터치 센서)을 누르면, Python의 TTS(예: `gTTS` 또는 `pyttsx3`) 모듈이 작동.
* **동작 시나리오:**
  * 관심 노선이 있을 때: "선택한 OOO번 버스는 약 O분 후 도착 예정입니다." 음성 출력.
  * 관심 노선이 없을 때: "관심 노선을 먼저 선택해 주세요." 음성 출력.
* **출력 매체:** 정류소 키오스크 역할을 하는 PC에 연결된 스피커 사용.

### 3.8. 휴대폰 안내 페이지
* **구현 방식:** Streamlit 애플리케이션을 네트워크(Local 또는 Public)에 호스팅.
* **접근 방법:** Python 라이브러리(예: `qrcode`)를 사용해 해당 웹 주소를 담은 QR코드를 생성하고 화면 한편에 항시 표시.
* **모바일 기능:** 사용자가 스마트폰으로 QR 스캔 시 모바일 웹 브라우저로 접속되며, PC와 동일한 실시간 도착 정보 확인 및 관심 노선 선택 기능 제공.

## 4. 하드웨어 핀 맵 (예시)

| 부품명 | Arduino UNO R4 핀 | 용도 및 설명 |
| :--- | :--- | :--- |
| 버튼 1 | Digital 2 (INPUT_PULLUP) | 다음 노선 이동 (관심 노선 선택용) |
| 버튼 2 | Digital 3 (INPUT_PULLUP) | 선택 / 해제 (관심 노선 선택용) |
| 큰 버튼(터치) | Digital 4 (INPUT_PULLUP) | 음성 안내 요청용 |
| 네오픽셀 (LED) | Digital 6 | 도착 임박 시각적 알림 (데이터 핀) |
| 부저 (Buzzer) | Digital 8 | 도착 임박 청각적 알림 |

## 5. 데이터 통신 방식 (PC ↔ 아두이노)

아두이노 UNO R4 WiFi의 장점을 살려 통신 방식을 선택할 수 있습니다. 
* **옵션 A (USB 시리얼 통신):** 가장 안정적이고 구현이 쉽습니다. Python의 `pyserial`을 사용해 JSON 형태로 데이터를 주고받습니다.
* **옵션 B (WiFi 통신 - HTTP/WebSocket):** 선 없이 깔끔한 배치가 필요할 경우 사용합니다. 아두이노를 로컬 웹서버로 만들거나, Python 서버와 WebSocket으로 실시간 통신합니다.

**[데이터 교환 포맷 예시 (JSON)]**
* **PC -> 아두이노 (명령):** `{"led_status": "alert", "buzzer": "on"}`
* **아두이노 -> PC (상태):** `{"btn_next": 1, "btn_select": 0, "btn_voice": 0}`

## 6. 개발 단계 요약
1. **API 연동 테스트:** Python으로 공공데이터포털 버스 OpenAPI 데이터를 가져오고 파싱하는 콘솔 스크립트 작성.
2. **UI 프로토타입 구현:** Streamlit을 활용하여 데이터 표출 및 화면(웹, 모바일 뷰) 레이아웃 구성.
3. **하드웨어 구성 및 펌웨어 작성:** 아두이노에 버튼, LED, 부저를 회로 구성하고 입력/출력 테스트 코드 작성.
4. **PC-아두이노 통신 연동:** 시리얼 또는 WiFi를 통해 Streamlit과 아두이노가 양방향으로 상호작용하도록 통합.
5. **부가 기능 추가:** TTS 음성 합성 및 QR 코드 생성 기능 추가 연동.
6. **디버깅 및 최적화:** 중복 알림 방지 로직 점검 및 현장(테스트 환경) 사용성 테스트.
